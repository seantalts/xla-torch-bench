# XLA:CPU vs PyTorch (Inductor) CPU Benchmarks — Design

## Goal

A standalone Python benchmark suite for measuring XLA:CPU codegen quality against `torch.compile`/Inductor on a shared set of workloads. Primary audience: XLA:CPU codegen iteration (fusion emitters, tiling, vectorization). Secondary: detecting regressions on PyTorch-side changes.

Each benchmark is a "rosetta stone" — written twice, once as a PyTorch `nn.Module` and once as a JAX function, expressing the same compute idiomatically. The PyTorch side runs through `torch.compile(backend="inductor")`. The JAX side runs through `jax.jit`, which dispatches to XLA:CPU.

## Non-goals

- Whole-model accuracy comparisons. The harness checks numerical equivalence to guard the rosetta-stone invariant, but accuracy is not a reported metric.
- GPU benchmarks. CPU only.
- Continuous integration against XLA's dashboard. The repo lives outside XLA tree; CI gating is not in scope for v1.
- TensorRT / OpenVINO / IREE. Architecture allows adding more backends later but v1 ships XLA:CPU vs PyTorch only.

## Why standalone (vs in-tree under `xla/backends/cpu/benchmarks/`)

- PyTorch is heavyweight in the XLA bazel tree; in-tree forces every harness change through XLA review.
- Standalone repo lets us swap which XLA wheel is installed (`pip install jax[cpu]` for stock, or built-from-source jax/xla for codegen experiments) without touching the harness.
- Out-of-tree means we eat the cost of XLA API drift. Accepted.

## The benchmark contract

Each benchmark file exports one `Spec` via the `@register` decorator. Skeleton:

```python
# benchmarks/norms/rms_norm.py
from xtbench import register, Spec
import torch, torch.nn as nn
import jax, jax.numpy as jnp

@register
def rms_norm() -> Spec:
    def torch_module(d):
        class M(nn.Module):
            def __init__(self):
                super().__init__()
                self.w = nn.Parameter(torch.ones(d))
            def forward(self, x):
                rms = torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + 1e-6)
                return x * rms * self.w
        return M()

    def jax_fn(d):
        w = jnp.ones((d,))
        def f(x):
            rms = jax.lax.rsqrt(jnp.mean(x * x, -1, keepdims=True) + 1e-6)
            return x * rms * w
        return f

    return Spec(
        torch_module=torch_module,
        jax_fn=jax_fn,
        shapes=[(1, 1024, 768), (1, 4096, 768)],
        dtypes=["f32", "bf16"],
        params={"d": lambda shape: shape[-1]},
    )
```

Design notes:

- **No HLO text anywhere.** Both sides are idiomatic Python. Benchmark files stay short and readable.
- **`params` is the only escape hatch** for benchmark-specific shape-derived constants. Avoids spec-API sprawl.
- **One input per (shape, dtype)**, generated by the harness from a fixed seed and converted to both `torch.Tensor` and `jax.Array` for the two sides.

## Measurement protocol (strict apples-to-apples)

For each `(spec, shape, dtype)`:

1. **Pin threads before any framework import.** `cli.py` sets `OMP_NUM_THREADS`, `MKL_NUM_THREADS`, and `XLA_FLAGS=--xla_cpu_multi_thread_eigen=true --xla_cpu_eigen_num_threads=N` from CLI args, then imports torch/jax. `torch.set_num_threads(N)` after import as belt-and-suspenders.
2. **Generate input as `np.ndarray`** with a fixed seed; convert to `torch.from_numpy(...)` and `jnp.asarray(...)`.
3. **PyTorch side**: `m = torch.compile(spec.torch_module(...), backend="inductor")`. First call is the compile; record `compile_t_torch` separately. Then `WARMUP` warmup calls, then `ITERS` timed calls (`time.perf_counter_ns` around `m(x_torch)`).
4. **JAX side**: `f = jax.jit(spec.jax_fn(...))`. First call triggers tracing+compile; `block_until_ready()` to force materialization, record `compile_t_jax`. Then `WARMUP` warmup calls (each followed by `block_until_ready`), then `ITERS` timed calls with the same blocking.
5. **Equivalence check**: run both once more, assert `np.allclose(m(x_torch).detach().numpy(), np.asarray(f(x_jax)), atol=tol_for(dtype))` where `tol_for("f32")=1e-4`, `tol_for("bf16")=1e-2`. If it fails, the row is marked `EQUIV FAIL` and no times are reported.
6. **Stats**: report median, p10, p90 over the `ITERS` samples. No `mean`.

Defaults: `WARMUP=5`, `ITERS=50`, `threads=os.cpu_count()`. All CLI-overridable.

Compile time is recorded and printed in a separate trailing line, never folded into steady-state.

```
$ xtbench --threads 8 --dtypes f32,bf16 --filter "rms|attention"

benchmark                shape              dtype  torch (ms)        xla (ms)         speedup
rms_norm                 (1,1024,768)       f32    0.42 [0.40,0.45]  0.31 [0.30,0.33]  1.35x
rms_norm                 (1,1024,768)       bf16   0.28 [0.27,0.30]  0.22 [0.21,0.24]  1.27x
rms_norm                 (1,4096,768)       f32    1.61 [1.58,1.70]  1.20 [1.18,1.25]  1.34x
mha_block                (1,512,12,64)      f32    3.10 [3.05,3.30]  3.40 [3.35,3.50]  0.91x
...

compile time (median, first-call): torch 412 ms / xla 285 ms across 14 benchmarks
```

- `speedup = torch_median / xla_median`. `>1` means XLA faster.
- `[p10, p90]` in brackets after each median.
- `EQUIV FAIL` replaces the times for any row whose equivalence check tripped.
- No persistent JSON in v1. `report.py` is the only file that would change to add it later.

CLI flags (v1):

- `--filter REGEX` — regex on benchmark name; default all.
- `--threads N` — thread pin count; default `os.cpu_count()`.
- `--dtypes f32,bf16,...` — comma list; default all dtypes declared in each spec.
- `--shapes "..."` — optional, comma-separated shape tuples to override spec shapes.
- `--warmup N` / `--iters N` — override defaults.

## Initial benchmark seed

Microbenchmarks across the four categories:

| Category | Benchmarks |
|---|---|
| Elementwise fusion | `add_chain` (a+b+c+d), `gelu_chain` (linear → gelu → linear), `silu_mul` (silu(a)*b — SwiGLU half), `add_mul_aligned_vs_misaligned` (xtile boundary cases) |
| Reductions + norms | `layer_norm`, `rms_norm`, `softmax`, `sum_axis`, `mean_axis` |
| GEMM | `dot_small` (256³), `dot_medium` (1024³), `dot_bias_gelu` (matmul+bias+gelu), `dot_transpose` |
| Attention | `mha_block` (Q@K → softmax → @V; head_dim 64; seq 128/512/2048), `gqa_block` (grouped QA, LLM shapes) |

E2E (small, no weight downloads):

- `gpt2_block` — one GPT-2 transformer block, forward only, randomly initialized.
- `mlp_mixer_block` — attention-free alternative for a different fusion profile.

`add_mul_aligned_vs_misaligned` is the deliberate synthetic that should make xtile-aligned-ops gains visible as a single row in the output table.

## Testing

`tests/test_equivalence.py` iterates the registry and runs the harness's equivalence check on every `(spec, shape, dtype)` triple. Failure means a rosetta-stone benchmark is broken and must be fixed before merge.

No timing tests; benchmarks are flaky as functional tests.

## Stretch (not in v1)

- `xtbench dump <bench>` — write `jax.jit(f).lower(...).as_text()` (XLA HLO) and Inductor wrapper code (`torch._inductor.config.trace.enabled=True`) to disk for inspection. Single most useful add for codegen work; cheap to implement.
- Thread-count sweep mode.
- Persistent JSON output for trend tracking and dashboarding.
- Additional backends: TensorRT, OpenVINO, IREE.
- AOT comparison: XLA via `jax.export`, PyTorch via AOTInductor.

## Open questions

- macOS thread-pinning fidelity. Linux `taskset` would be cleaner; on macOS we rely on env vars only. Acceptable for v1.
- BF16 on platforms without native bfloat16 (older Intel CPUs). `torch.compile` may fall back to upcast; JAX likewise. Document; don't paper over.
